# Fuhrpark Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Neuer Bereich „Organisation → Fuhrpark“: Fahrzeuge einer Organisation in Gruppen, gespeicherte Kontrollrunden mit „Erledigt“, Markdown-Ausgabe im Format des Auftraggebers.

**Architecture:** Neue Organisationsfunktion `fleet` (Rechte über `team_level`), Migration 027 mit vier Tabellen, Routen in `src/routes/fleet.js`, reine Ausgabe-Funktion `src/fleet-markdown.js` (ohne DB, Unit-Test), Seite `pages/fleet.js`. Keine Verbindung zu `vehicles`.

**Tech Stack:** Node 22, Fastify 5, zod, pg (handgeschriebenes SQL), Vanilla-JS-Frontend ohne Build.

**Spec:** `docs/superpowers/specs/2026-11-11-fuhrpark-umbuchungen-akten-pdf-design.md` Abschnitt 1

## Global Constraints

- Alle Regeln aus `AGENTS.md` (Fallstricke) gelten; UI-Texte deutsch, Du-Form, echte Umlaute.
- Code/DB/API heißen `fleet`; in der Oberfläche „Fuhrpark“.
- Fuhrpark gehört immer einer Organisation (`team_id NOT NULL`), es gibt kein Solo.
- Notizen sind reiner Text: kein `markdown: true`, kein `markdownBlock`.
- Rechte `fleet`: Stufen `[0, 2, 3, 4]`; 2 = sehen + Markdown, 3 = Fahrzeuge/Gruppen pflegen, Runden anlegen, erfassen, erledigt setzen, 4 = erledigte Runden ändern/zurücknehmen, löschen.
- Vorgaben für Ränge: Leitung 4, Mitglied 2, Leser 2.
- Teil-Updates nur mit `patchSchema()`; neue Felder in `LABELS` (`validation.js`).
- Strikte CSP: kein Inline-JS, keine `on*`-Attribute.
- Tests nur auf `bm-check` (18089), nie auf 8088.

## Review Focus

- Kennzeichen doppelt in derselben Organisation (aktiv) → 400 mit verständlicher Meldung statt 500 (23505 abfangen, auch beim PATCH/Reaktivieren).
- Notiz mit `|` oder Zeilenumbruch → Markdown-Tabelle bleibt intakt (`\|`, Umbruch → Leerzeichen).
- Runde ohne Vorgänger (erste Runde) → Zeilen leer, kein Fehler; Fahrzeug neu seit letzter Runde → leere Zeile.
- Mitglied mit Stufe 3 versucht erledigte Runde zu ändern oder `done=false` zu setzen → 403.
- Fremde Organisation (Stufe 0) ruft Runde/Fahrzeug per ID ab → 404 (IDOR).

- Produces (alle unter `/api`, Katalogrecht in Klammern, Stufe in `fleet`):
  - `GET /fleet/teams` (`fleet:read`) → Organisationen mit `level` ≥ 2: `[{ id, name, level }]`.
  - `GET /fleet/groups?team_id=` (read, 2) → `[{ id, name, show_model, sort, vehicles: int }]`; `POST /fleet/groups` (create, 3) `{ team_id, name, show_model?, sort? }`; `PATCH /fleet/groups/:id` (update, 3); `DELETE /fleet/groups/:id` (delete, 4; 400 „Gruppe enthält noch Fahrzeuge“ wenn Fahrzeuge dran).
  - `GET /fleet/vehicles?team_id=&all=1` (2; ohne `all` nur aktive) → `[{ id, group_id, group_name, plate, model, note, sort, active }]`; `POST /fleet/vehicles` (3) `{ team_id, group_id, plate, model?, note?, sort? }`; `PATCH /fleet/vehicles/:id` (3, inkl. `active`); `DELETE /fleet/vehicles/:id` (4; 400 „Fahrzeug kommt in Kontrollrunden vor – bitte ausmustern“ wenn Items existieren).
  - `PUT /fleet/vehicles/order` (3) `{ team_id, ids: uuid[] }` setzt `sort` nach Reihenfolge.
  - `GET /fleet/checks?team_id=` (2) → `[{ id, checked_on, done, done_at, done_by_name, items: int }]` neueste zuerst.
  - `POST /fleet/checks` (3) `{ team_id, checked_on? }` (Vorgabe `today()`) → legt Runde an, je aktivem Fahrzeug ein Item mit Kopie von Gruppe/Kennzeichen/Modell/Sort und Werten des Items desselben Fahrzeugs aus der zuletzt angelegten Runde (`ORDER BY checked_on DESC, created_at DESC`); → `{ id }`.
  - `GET /fleet/checks/:id` (2) → `{ check, items }` (Items sortiert nach `group_sort, group_name, vehicle_sort, plate`).
  - `PATCH /fleet/checks/:id` (3; bei `done=true` gespeicherter Runde 4) `{ checked_on?, done?, items?: [{ id, odometer_km?, last_service_on?, first_aid_kit_until?, accessories_complete?, note? }] }`. `done` true→ setzt `done_at/done_by`; `done` false auf erledigter Runde braucht 4. Änderung einer erledigten Runde → `audit(req, 'fleet_check.updated_after_done', 'fleet_check', id)`.
  - `DELETE /fleet/checks/:id` (delete, 4).
  - `GET /fleet/checks/:id/markdown` (2) → `text/markdown; charset=utf-8`, Body = `fleetMarkdown(…)`.
- Fehlertext bei doppeltem Kennzeichen: „Dieses Kennzeichen gibt es in diesem Fuhrpark schon“.
